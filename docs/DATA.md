# klawnavi のデータの形

1つのジャンル（情報・個人情報、食品衛生 …）は、`data/genres/<id>.json` の1ファイルと、
その根拠の法令の一覧 `data/laws_<id>.json`（`{"法令名": "法令番号"}`）でできています。
条文は `scripts/fetch_law.py --genre <id>` が e-Gov法令検索 法令API v2 から取り、`data/law_<id>.json` に書きます。

**`scripts/verify_law.py` を通さずに公開しません。** 条番号が実在するか、`expect` の語が条文の本文にあるか、
条件に書いた質問と選択肢が実在するかを、全項目で突き合わせます。

## ジャンルのファイル

```json
{
 "id": "privacy",
 "title": "情報・個人情報",
 "standards": ["ISO/IEC 27001", "プライバシーマーク（JIS Q 15001）"],
 "summary": "このジャンルで何が分かるかを1〜2文で",
 "questions": [ … ],
 "items": [ … ]
}
```

## 質問（questions）

AI が上から順に1問ずつ聞きます。`show_if` に当たらない質問は飛ばします。

```json
{
 "id": "q_mynumber",
 "label": "マイナンバーの収集",
 "text": "従業員やアルバイトのマイナンバーを、給与や社会保険の手続きのために集めていますか？",
 "why": "マイナンバーは、ふつうの個人情報より扱いの決まりが厳しいからです。",
 "type": "yesno",
 "options": [{"v": "yes", "label": "集めている"}, {"v": "no", "label": "集めていない"}],
 "show_if": ["q_staff=yes"],
 "show_if_any": []
}
```

- `label` は質問の短い見出し（15字くらいまで）。チェックシートの「当てはまった理由」に「マイナンバーの収集：集めている」の形で出ます。
- `type` は `yesno`（はい・いいえ）・`single`（1つ選ぶ）・`multi`（いくつでも選ぶ）。
- 「わからない」の選択肢は画面が自動で足します（値は `unknown`）。データに書かないでください。
  「わからない」と答えた質問に関係する項目は、消さずに **要確認** としてチェックシートに残ります。
- 利用者は選択肢を押すほか、自由に文章で答えることもできます。その文章は AI が選択肢に直します。
  だから選択肢の `label` は、利用者の言葉で区別がつくように書きます。
- `text` は、法律に詳しくない担当者が答えられる聞き方にします（法令名で聞かない。「〜法の対象ですか」と聞かない）。

## チェック項目（items）

```json
{
 "id": "anzen-kanri",
 "title": "個人データの安全管理措置",
 "law": "個人情報の保護に関する法律",
 "articles": ["23"],
 "expect": ["安全管理"],
 "duty": "個人データの漏えい・滅失・毀損を防ぐため、必要で適切な安全管理の措置をとる。",
 "freq": "常時（年1回は見直す）",
 "check": "社内規程・アクセス権限の一覧・持ち出しのルールがあり、守られているかを確かめる。",
 "records": "安全管理の規程、アクセス権限の一覧、点検の記録",
 "need": ["q_personal=yes"],
 "need_any": [],
 "region": "全国"
}
```

- `need` は全部満たすとき、`need_any` はどれか1つ満たすときに出ます。どちらも空なら、そのジャンルを選んだ全員に出ます。
- 条件は `質問id=値`（`multi` の質問なら「その値を選んだ」）か `質問id!=値`。
- `law` は `data/laws_<id>.json` に書いた名前と同じにします。`articles` は e-Gov の条番号（第二十六条の二なら `26_2`）。
- `expect` には、その条文の本文に**そのまま出てくる語**を入れます（改正で条文が動けば検算で落ちます）。
- 法令以外（自治体の条例・告示・国のガイドライン）は `region` に「愛知県」「名古屋市」など、または「全国（ガイドライン）」と書き、
  `source_url`（公式ページ）と `checked`（確かめた日 `2026-11-25`）を必ず付けます。`articles` と `expect` は要りません。
- `duty` `check` は担当者がそのまま読める言葉で。条文の写しではなく、何をすればよいかを書きます。
- 罰則や金額など、条文で確かめていないことは書きません。
